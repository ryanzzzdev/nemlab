# NEMLab project documentation

These instructions apply to NEMLab planning and implementation in this project directory.

- Use the `project-management` skill for NEMLab work. If it is not in the skill catalogue, read `/home/ryan/.codex/skills/project-management/SKILL.md` when available. If unavailable, follow the documentation guide directly.
- The canonical guide currently lives at `docs/project/documentation-guide.md`, relative to this file. Read it before meaningful project work and follow its file ownership and update conventions.
- Before ending a turn that changes implementation, produces substantive investigation findings, records an accepted planning decision, or delivers project documentation, update the affected project records and journal. Do this as part of the authorised work without a separate reminder.
- Update only affected documents; do not create empty trackers or duplicate records. Pure explanations and unchanged status checks need no entry. Keep proposals distinct from accepted decisions, and unfinished or unverified work distinct from Done.
- NEMLab uses the journal location and format from its documentation guide for this workflow; do not also write the same outcome to a generic work-journal location.
- Every journal entry must identify the LLM model and coding agent used. Use reliable session information, distinguish model family from exact variant, and record unknown details explicitly rather than guessing.
- This file belongs to the NEMLab backend project root. When the NEMLab frontend is created, add equivalent scoped instructions there pointing to this backend's canonical documentation. Do not assume these instructions are loaded when working in a separately opened frontend repository.
